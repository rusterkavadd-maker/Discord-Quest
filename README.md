# Discord-Quest
Авто-Выполнение заданий Дискорд.

# Наебщик Дискорда 4.1

Настольное приложение для Windows 10, которое закрывает Discord-квесты двумя способами:

1. **Пустышка** — копия системного `notepad.exe` (или другого) под именем exe реальной игры.
   Discord сканирует процессы, видит совпадение имени и засчитывает «играл в игру».
2. **Автоквесты** — прямые запросы к API Discord: принять квест, прокрутить видео,
   отбить heartbeat, забрать награду. Работает без запуска чего-либо вообще.

Оба способа независимы. Можно пользоваться только вторым.

---

## 1. Требования и запуск

- Windows 10 (на 11 не проверялось, часть системных exe там стали заглушками Store).
- Python 3.8+ с галкой **tcl/tk** при установке. Проверка: `py -c "import tkinter"` без ошибок.
- Открытый клиент Discord (иначе не будет ни детекта, ни IPC).
- Пользовательский токен Discord — **не ботовский**.

Запуск:
py quest_app.py

Токен берётся так: в Discord `Ctrl+Shift+I` → вкладка **Network** → любое действие на странице квестов →
запрос `quests/@me` → заголовок `Authorization` → скопировать значение (без слова `Bearer`).
Токен живёт примерно месяц, потом надо брать новый.

| Что | Путь |
|---|---|
| Конфиг | `%USERPROFILE%\.discord-quest-fake.json` |
| Папка пустышек (по умолчанию) | `%LOCALAPPDATA%\discord-quest-fake\games\` |

Конфиг хранит токен, режим автоквестов, папку, галочки и геометрию окна. Удалить его — сбросить всё к дефолту.

## 3. Как работают пустышки

### 3.1. Идея

Discord определяет «играю в игру» по имени исполняемого файла процесса. Значит достаточно запустить
любой процесс с именем `EscapeFromTarkov.exe` — и Discord засчитает игру. Приложение берёт
системный exe (лёгкий, уже есть в Windows) и кладёт его копию под нужным именем.

Кандидаты по порядку: `notepad.exe`, `mspaint.exe`, `charmap.exe`, `osk.exe`, затем консольный `ping.exe`.

### 3.2. Проблема MUI и её решение

Системные exe — MFC-приложения. Они грузят свои локализованные ресурсы из подпапок вида
`System32\ru-RU\notepad.exe.mui`. Когда exe **переименован и унесён** в другую папку, ресурс
не находится, и приложение падает с окном «Не удалось создать новый документ», а затем
выходит с кодом 0.

Решение — `copy_mui()`: рядом с пустышкой раскладываются языковые папки с переименованным
`.mui`-файлом (`Endfield.exe.mui`). Дополнительный предохранитель: `notepad` получает
аргументом пустой `.txt`, чтобы вообще не заходить в ветку «создать новый документ».

### 3.3. Хардлинк вместо копирования

`FakeGame._place()` сначала пробует `os.link()` — жёсткую ссылку. Это мгновенно и не тратит
диск. Если целевой диск другой (хардлинки работают только внутри тома), откат на `shutil.copyfile()`.

### 3.4. Надзор

`FakeGame._supervise()` раз в секунду проверяет, жив ли процесс. Если процесс умер за < 4 секунд —
значит источник не подходит, и надзор **сразу** переключается на следующего кандидата
(`src_i += 1`) и снимает оставшиеся процессы `taskkill`. Если прожил дольше — просто перезапускает
тот же источник.

## 4. Как работают автоквесты

### 4.1. Общий поток
GET /users/@me — проверка токена, получение своего id
GET /quests/@me — список квестов
↓ для каждого квеста
определить тип задачи (task_kind)
если срок истёк → пропустить
если тип не поддержан → пропустить с записью ключей в лог
если уже completed_at → сразу claim, если он не забран
если не enrolled → POST /quests/{id}/enroll
↓ запустить обработчик по типу
WATCH_VIDEO → POST /quests/{id}/video-progress (цикл до completed_at)
PLAY_ON_DESKTOP → POST /quests/{id}/heartbeat (цикл ~25 с) [+ пустышка в режимах hybrid/process]
PLAY_ACTIVITY → POST /quests/{id}/heartbeat со stream_key
STREAM_ON_DESKTOP → то же + предупреждение в лог
↓
POST /quests/{id}/claim-reward — для всего, что доехало до completed_at

Задачи идут двумя параллельными потоками: «лёгкие» (видео и активности) — по одной за раз,
«тяжёлые» (игры) — по одной за раз. Между ними случайные паузы 4–18 с. Порядок квестов
перемешивается случайно.

### 4.2. Три режима зачёта игровых квестов

| Режим | Что делает | Следы |
|---|---|---|
| `api` (по умолчанию) | Ничего не запускает. Только heartbeat с правдоподобным путём `C:\Program Files\<Игра>\<exe>` | Единственный источник heartbeat, путь как у настоящей установки |
| `hybrid` | Heartbeat + поднимает окно-пустышку | Клиент видит процесс и тоже отбивает heartbeat, путь в AppData |
| `process` | Только окно, heartbeat не дублируется. Если за 90 с прогресс не пошёл — включает heartbeat сам | Путь в AppData, зато есть живой процесс |

Режим `api` — самый «тихий»: ни одного лишнего процесса, ни одного дублирующего запроса.

### 4.3. Тайминги (специально как у живого клиента)

- **Видео**: запрос раз в 7–9.5 с, приращение равно реально прошедшему времени, к timestamp
  добавляется `random()`. Это ровно цикл плеера Discord. Итог — квест идёт столько же, сколько
  длится видео. Галочка «Ускорять видео» ломает это сознательно: шаг 8 с за 1.5 с, примерно 4×.
- **Heartbeat**: интервал 20–30 с (у клиента 60 с, у нас чаще — так прогресс идёт ровно по часам).
- **Добивка**: если цель достигнута по timestamp, но `completed_at` не пришёл, приложение
  до 30 раз шлёт `{timestamp: target}` с паузами 4–7 с.
- **Пустышка живёт** `target + 15…120` с, а не ровно цель — живой игрок не закрывает игру в ту же секунду.
- **Claim** откладывается на 30–240 с и уходит с `location: 2` (Gift Inventory), как у живого человека.
- **Enroll** откладывается на 2–10 с и уходит со случайным `location` из (11, 10, 2).

### 4.4. Что кладётся в запросы и почему

- `traffic_metadata_sealed` из записи квеста — обязательно в enroll и claim. Без него запрос
  отличим от настоящего клиента, потому что у живого это поле всегда есть.
- В claim **только** `location`, `platform`, `traffic_metadata_sealed`. Лишние ключи палят так же,
  как пропущенные.
- `X-Super-Properties` собирается с настоящим `client_build_number` (скрапится с `discord.com/app`),
  реальным `os_version` и локалью.
- `executable_path` в heartbeat — правдоподобный путь. `executable_fingerprint` не отправляется
  вообще: у фейка нет процесса для аттестации, а выдуманное значение было бы хуже пустого.

### 4.5. Токен, лимиты, блокировки

- 429 — пауза по `retry_after` и повтор, до 3 попыток. 5xx — экспоненциальный откат.
- 401 — «токен протух», запись в лог и выход.
- `quest_enrollment_blocked_until` и `quest_access_suspended_until` из ответа читаются и печатаются.
  Если Discord выдал блокировку за автоматизацию — будет видно её дату.
- Claim может упереться в капчу. Тогда в ответе есть `errors`, приложение пишет
  «заберите вручную в Gift Inventory» и не считает это ошибкой.

## 5. Гайд: закрыть ОДИН квест через пустышку

1. В Discord прими квест вручную (кнопка «Играть» / «Получить»).
2. В приложении → вкладка **«Поиск игр»** → введи название игры латиницей → Enter.
3. Двойной клик по нужной строке — игра уйдёт во вкладку «Очередь».
   Если игра не находится — возьми другую с тем же типом задачи, Discord считает по названию
   приложения, а не по конкретному exe.
4. В сайдбаре выставь **«Длительность, минут»** = требуемое время квеста + 2–3 минуты,
   «Случайный довесок» = 60.
5. Включи в Discord **Настройки → Игровая активность → «Отображать текущую активность»**.
6. Жми **СТАРТ** (или `Ctrl+Enter`). Откроется окно с именем игры, заголовок переименуется в название игры.
7. Не закрывай приложение до конца отсчёта. Прогресс смотри в Discord.
8. После завершения забери награду в **Настройки → Подарки**.

Если игра не засчиталась — в журнале будет строка `виден в системе: НЕТ`, значит имя exe
не совпало с тем, что ждёт Discord. Возьми игру через вкладку «Активные квесты» (там exe
подбирается автоматически из базы детекта).

## 6. Гайд: закрыть ВСЁ через автоквесты

1. Вкладка **«Активные квесты»** → вставь токен → **«Дамп»**.
   В журнале должно быть `quests N, excluded M, blocked …, suspended …`. Если `quests 0` —
   смотри файл `%TEMP%\quests_dump.json`, там видно причину.
2. Вкладка **«Автоквесты»** → режим оставь `api` (тихо, без окон). Если хочется видеть окна —
   `hybrid`. Галочки «Принимать квесты» и «Забирать награды» оставь включёнными.
3. Жми **«ВЫПОЛНИТЬ ВСЁ»**.
4. Таблица внизу показывает по каждому квесту тип, цель и статус. Строки, которые не удалось
   взять, помечаются причиной: `истёк`, `не умею`, `принять не удалось`, `недобор`.
5. Ничего не делай. Видео идут по реальному времени, игры — по реальному времени, активности —
   по реальному времени. Всё параллельно, максимум две задачи одновременно.
6. По окончании проверь журнал: строки `пройден` и `награда получена`. Что осталось — либо
   `награда вручную` (капча), либо пропущено осознанно.
7. **СТОП** прерывает всё немедленно и убивает пустышки.

Если у квеста написано «Для начала выберите платформу» — открой карточку в Discord и один раз
выбери платформу, иначе `enroll` отобьётся 403/404.

## 9. Что не работает и почему

| Задача | Статус |
|---|---|
| `ACHIEVEMENT_IN_GAME` | Нужна настоящая игра с привязанным аккаунтом. Пропускается |
| `ACHIEVEMENT_IN_ACTIVITY` | Требует OAuth-авторизацию приложения и POST на `discordsays.com`. Пропускается |
| `PLAY_ON_XBOX`, `PLAY_ON_PLAYSTATION` | Нужна привязка консольного аккаунта. Пропускается |
| `STREAM_ON_DESKTOP` | Heartbeat уходит, но Discord может требовать реального «Go Live» с кем-то в войсе. Если прогресс не идёт — стрими вручную |
| Квесты с «выберите платформу» | Нужно один раз выбрать платформу в UI Discord, иначе `enroll` отобьётся |
| Claim с капчей | Забрать вручную в Настройки → Подарки |

## 10. Про палево

Что выглядит как живой игрок: единственный источник heartbeat, путь `C:\Program Files\...`,
кадр видео ровно как у клиента, по одной игре за раз, случайные паузы, claim через несколько
минут, настоящий build-номер в заголовках.

Что всё равно видно и убрать нельзя: отсутствие `executable_fingerprint` (192-байтная нативная
аттестация бинарника, у фейка её нет), отсутствие капчи при claim, отсутствие обычной
активности в клиенте в момент квеста.

**Discord с апреля 2026 реально наказывает за автоматизацию квестов** — временная блокировка
квестов на 10–15 дней плюс запись в Account Standing. Ловили и скрипты, и completer-тулзы,
и переименованные exe с кастомными путями. Гарантий нет ни у одного способа. Единственный
стопроцентно безопасный вариант — играть руками.

## 11. Частые проблемы

| Симптом | Что делать |
|---|---|
| «Не удалось создать новый документ» | Не хватает MUI. Проверь, что в папке пустышки есть подпапки `ru-RU` / `en-US` с `.mui`. Если их нет вообще — надзор сам переключится на `mspaint`/`charmap` |
| Окно не появляется, `виден в системе: НЕТ` | Имя exe не совпало. Бери игру через вкладку «Активные квесты» |
| «Автоквесты: список пуст» | Жми «Дамп», смотри `%TEMP%\quests_dump.json`: либо токен не тот, либо аккаунт на блокировке |
| «Автоквесты: не умею: ...» | Ключи задач не поддержаны. Скинь строку — добавится маппинг |
| «принять не удалось (403/404)» | Квест требует выбора платформы или возрастного подтверждения |
| «heartbeat не идёт» | Прогресс не растёт: включи «Отображать текущую активность» или переключись на режим `hybrid` |
| Токен отвалился через месяц | Взять свежий из DevTools |
| Discord показывает «Playing» лишний раз | Режим `hybrid` — это норма, клиент видит пустышку |
